# AI Connector — Telegram

Двусторонний MCP-сервис для Telegram: получает сообщения и файлы от подтверждённых пользователей, даёт чату читать входящие и отвечать в исходный диалог. Стабильная версия **1.1.0** использует только бота и long polling. Личные Telegram-аккаунты и OpenAI API не используются.

Бот в Telegram называется **AI Connector**, а плагин в AI-чате — **Telegram**.
Бот работает с MCP-совместимыми AI-приложениями; модель выбирается в подключённом приложении. Иконка находится в `assets/`; тексты профиля и меню команд — в `assets/bot-profile.json`.

Работайте в корне репозитория. Настройка проекта в среде разработки и регистрация подключения к MCP-серверу выполняются отдельно: команды ниже не регистрируют приложение автоматически.

## Требования

- Python 3.12 или новее и `uv` для локального запуска.
- Telegram-бот, созданный через `@BotFather`.
- Docker Compose для запуска в контейнере.

## Локальный запуск

В PowerShell скопируйте пример настроек:

```powershell
Copy-Item .env.example .env
```

В Linux или macOS:

```sh
cp .env.example .env
```

Заполните `.env`: укажите токен бота и создайте отдельный MCP-токен не короче 32 символов. Не отправляйте эти значения в чат, логи или систему контроля версий. Файл `.env` уже исключён из Git.

В Telegram откройте официальный `@BotFather`, выполните `/newbot` и сохраните выданный токен в `TELEGRAM_BOT_TOKEN`. Для `MCP_AUTH_TOKEN` используйте случайную строку из печатных ASCII-символов без пробелов, например результат локальной команды `uv run python -c "import secrets; print(secrets.token_urlsafe(32))"`. Для групп добавьте бота в нужную группу и внесите её отрицательный числовой ID в `ALLOWED_GROUP_CHAT_IDS`; права администратора для обычной отправки обычно не требуются, но бот должен иметь право писать в выбранную группу/тему.

Установите зависимости проекта и проверьте конфигурацию:

```sh
uv sync --frozen
uv run telegram-ping-mcp doctor
```

`doctor` работает офлайн и показывает только безопасную сводку состояния настроек. Он не проверяет доступность Telegram и не выводит значения секретов.

Запустите HTTP-сервер на локальном компьютере:

```sh
uv run telegram-ping-mcp serve --transport http --host 127.0.0.1 --port 8000
```

MCP endpoint: `http://127.0.0.1:8000/mcp`. Каждый запрос к MCP, включая `tools/list`, требует авторизацию. Локальные операторские клиенты используют `Authorization: Bearer …`; публичные подключения поддерживают OAuth. `/health` открыт и возвращает только краткое состояние готовности.

Для запуска через stdio используйте `uv run telegram-ping-mcp serve --transport stdio`. В этом режиме HTTP-порт не открывается и MCP-токен не нужен; токен Telegram остаётся обязательным для работы бота.

Для MCP-клиента, поддерживающего stdio и конфигурацию `mcpServers`, пример подключения на Windows:

```json
{
  "mcpServers": {
    "telegram-ping": {
      "command": "uv",
      "args": ["--directory", "D:\\Projects\\telegram-mcp", "run", "telegram-ping-mcp", "serve", "--transport", "stdio"]
    }
  }
}
```

Клиент должен видеть `uv` в `PATH`; при необходимости укажите полный путь к `uv.exe`. `.env` загружается из каталога проекта. Если сервер уже запущен через Docker/HTTP, подключайтесь к его `/mcp`, чтобы не запускать второй poller. Статический MCP-токен сохраняет операторские права на все инструменты: передавайте его только доверенному клиенту. OAuth-подключения ограничены личной привязкой вошедшего пользователя.

Для локального клиента Codex можно настроить HTTP headers helper. Он читает только
`MCP_AUTH_TOKEN` из игнорируемого `.env` проекта и передаёт заголовок непосредственно
MCP-клиенту, без хранения секрета в `config.toml`:

```toml
[mcp_servers.telegram]
url = "https://mcp.example.test/mcp"
http_headers_helper = '"D:/Projects/telegram-mcp/.venv/Scripts/python.exe" "D:/Projects/telegram-mcp/scripts/mcp_headers.py"'
tool_timeout_sec = 300
```

Замените URL и пути на свои. Сначала выполните `uv sync --frozen`. Не запускайте
helper вручную с выводом на экран: его stdout содержит секретный заголовок.
Подключение через плагин ChatGPT использует OAuth; настройка описана ниже.

## Настройки

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | нет | Обязателен для `serve`; токен бота от `@BotFather`. |
| `MCP_AUTH_TOKEN` | нет | Обязателен для HTTP; не менее 32 символов. |
| `DATABASE_PATH` | `data/telegram-ping.sqlite3` | Путь к базе SQLite. |
| `LINK_TTL_SECONDS` | `900` | Срок действия ссылки для привязки пользователя. |
| `ALLOWED_GROUP_CHAT_IDS` | пусто | Разрешённые ID групп через запятую. Пустое значение запрещает отправку в группы. |
| `MCP_ALLOWED_HOSTS` | loopback | По умолчанию разрешены `127.0.0.1`, `localhost`, `[::1]` с любым портом. Пользовательский список заменяет этот набор. Имена через запятую без схемы URL; можно указать порт, например `mcp.example.test:443,localhost:8000`. Без порта разрешаются любые порты указанного имени. |
| `PUBLIC_MCP_URL` | пусто | Публичный HTTPS-адрес MCP, например `https://mcp.example.test/mcp`. Включает OAuth и добавляет адрес в `/connect`. Без пароля, токена, query и fragment. |
| `POLLING_ENABLED` | `true` | Включает получение обновлений бота через long polling. |
| `MAX_ATTACHMENT_BYTES` | `104857600` | Предел скачивания в MCP, максимум 100 МиБ. Облачный Bot API всё равно ограничен 20 МиБ. |
| `TELEGRAM_API_BASE_URL` | `https://api.telegram.org` | Облачный API либо явно настроенный локальный Bot API на loopback, например `http://127.0.0.1:18008`. |
| `TELEGRAM_LOCAL_FILES_ROOT` | пусто | Абсолютный закрытый каталог файлов локального Bot API в режиме `--local`. С облачным API не применяется. |

## Как работает привязка и отправка

Для подключения через OAuth пользователь отправляет `/connect` в личном чате с ботом. По подтверждённому Telegram обновлению сервер создаёт привязку только этого отправителя и сразу выдаёт инструкцию с одноразовым кодом входа. Отдельное приглашение не требуется. Новый `user_key` генерируется случайно; существующая привязка сохраняет свой ключ.

Операторский инструмент `create_user_link(user_key, display_name, ttl_seconds?)` остаётся доступен для заранее заданных внутренних ключей. Ссылка вида `https://t.me/ИМЯ_БОТА?start=…` — одноразовый секрет с ограниченным сроком действия. Она не нужна в обычном подключении через `/connect` и не переносит существующую привязку на другую личность.

Привязка не опирается на username и сама не переносится на другой Telegram ID. Команда `/unlink` удаляет привязку и отзывает доступ всех подключённых AI-приложений. Не публикуйте настоящие ссылки, ключи пользователей и личные данные в репозитории, примерах или логах.

Основной интерфейс бота — сворачиваемая клавиатура с кнопками «Подключить AI-приложение» и
«Отключить всё». Подключение открывает выбор ChatGPT, Claude или другого
AI-приложения. После выбора бот выдаёт короткую карточку: название, URL, OAuth
и код подключения с кнопками копирования. Шаги настройки для выбранного клиента
и сведения о приватности открываются отдельно кнопками; основной экран не
объединяет инструкции для всех приложений.

Бот отправляет PNG отдельным документом сразу после карточки настроек,
в ответ на выбор приложения или совместимую команду `/connect`.
Сообщение с иконкой также обновляет клавиатуру основных действий.
Если инструкция не доставлена, файл не отправляется; неоднозначные отправки
автоматически не повторяются. Кнопка скачивания в инструкции сохраняется как запасной вариант.
Публичный маршрут `/assets/telegram-icon.png` отдаёт только этот фиксированный
значок (256×256, меньше 10 КиБ), без доступа к пользовательским файлам.
Команда сразу создаёт личную привязку новому пользователю и выдаёт одноразовый код
входа без ограничения по времени, когда включён OAuth. Код расположен сразу после
полей плагина, перед завершением подключения и дополнительными пояснениями.
Повторный `/connect` заменяет предыдущий код; успешный вход расходует его, а `/unlink`
отзывает. Код хранится только в виде хеша и переживает перезапуск сервера.
Явное подключение или `/start` восстанавливает доступность личной привязки после разблокировки бота.
Сообщения из групп, от ботов и пересланные команды не создают привязку.

Инструкция и окно подтверждения объясняют границы доступа: подключённое
AI-приложение видит сообщения и файлы, отправленные именно этому боту; личный
Telegram-аккаунт, остальные переписки и контакты ему недоступны. Защита передачи
через HTTPS и проверка личной привязки не означают отсутствие обработки данных
сервисом. `/unlink` отзывает доступ, но не обещает удаление всех сохранённых данных.

До привязки клавиатура содержит только «Подключить AI-приложение». После привязки
добавляется «Отключить всё». Можно подключить ещё одно приложение, сохранив уже
выданные доступы. Кнопка отключения сначала просит
подтверждение; оно действует две минуты и относится только к текущей привязке.
Подтверждение и отмена находятся во временной reply-клавиатуре. Бот использует
одно сообщение подтверждения, удаляет его при выходе и восстанавливает основные
действия. Если прежнее сообщение нельзя удалить, новая форма не создаётся.
Открытие выбора приложения не создаёт новый код; код выдаётся после выбора клиента.
Управляющие кнопки не попадают во входящие AI-чата. Обычные
сообщения и файлы продолжают обрабатываться как входящие. Кнопки принимаются
только от самого пользователя в личном чате с этим ботом.

Навигация и действия доступны кнопками. Бот очищает slash-меню; `/start`
используется кнопкой Start в Telegram. Обработчики прежних команд подключения и
отключения сохранены для совместимости, но не предлагаются в интерфейсе.
Пауза, включение уведомлений и общая помощь удалены. Старые кнопки и `/stop`
только показывают актуальную клавиатуру, не меняя доступ, коды или привязку.
Карточка настроек, шаги и приватность разделены пустыми строками; заголовки
выделены явными Telegram entities, а значения сохраняют кнопки копирования.
Инструкция и приватность раскрываются в текущей карточке; «Назад» возвращает
настройки. Код и значения копирования сохраняются без нового выпуска кода.
При невозможности редактирования прежнее сообщение удаляется до замены;
неопределённый результат или неудача удаления не создают дубликат.

Пользователь отправляет боту `/connect`, добавляет MCP в AI-приложение по инструкции
и вводит полученный код в окне подключения. Затем можно отправить боту сообщение
или файл и попросить AI-чат проверить входящие. Автоматическое пробуждение чата
не реализовано.

### OAuth для AI-приложений

При заданном `PUBLIC_MCP_URL` сервер публикует OAuth metadata и protected resource
metadata. Поддерживаются динамическая регистрация клиентов (DCR), authorization
code с обязательным PKCE S256, ротация refresh-токенов и отзыв разрешений.
В ChatGPT выберите OAuth и DCR при добавлении сервера:
[настройка ChatGPT](https://developers.openai.com/api/docs/guides/custom-mcp-server).
Пользователь берёт код из `/connect`, вводит его на странице AI Connector и
подтверждает доступ. Сервер показывает домен адреса возврата приложения.

Привязку создаёт личная команда `/connect` от самого пользователя, а OAuth
подтверждает доступ приложения к его чату с ботом. Коды входа, коды авторизации, клиентские секреты и токены
хранятся только в виде хешей в отдельной закрытой SQLite рядом с основной базой.
Не включайте этот файл и его WAL в исходники или публичные резервные копии.
Сохраняйте OAuth-базу при обновлении, чтобы подключения переживали перезапуск.

Каждое OAuth-подключение видит только своего пользователя, его личные входящие и
файлы. Групповые отправки и создание приглашений остаются операторскими
инструментами. `/unlink` отзывает
разрешения приложений. OAuth подтверждает пользователя Telegram, но не определяет
отдельный AI-чат и не запускает его автоматически. Codex и другие HTTP-клиенты
могут использовать OAuth либо существующий операторский Bearer-токен.

Для подписей подключённых аккаунтов сервер предоставляет читающий инструмент
`get_profile` с метаданными `openai/profile`. Он возвращает только профиль текущего
OAuth-подключения: неизменный Telegram ID в виде строки и отображаемое имя.
При наличии никнейма используется `@username`; если его нет, окно подключения
просит задать имя аккаунта перед выдачей доступа. Изменение имени не меняет
личность, ключ привязки и разрешения. Операторскому токену профиль отдельного
человека не подставляется. Контракт профиля описан в
[документации OpenAI](https://developers.openai.com/plugins/build/auth#support-multiple-accounts).

Публичный интерфейс содержит четыре рабочих инструмента и служебный профиль.
`get_profiles` возвращает доступные активные аккаунты; `send_message` требует
точный `profile_id`. Если подключено несколько аккаунтов и получатель не указан,
чат должен спросить, какой выбрать. Имена и nickname сопоставляются только
с профилями и метаданными подключений, а не с содержимым входящих сообщений.
Каждый OAuth-запрос остаётся ограничен выбранным подключением. Администраторский
MCP-токен даёт операторский доступ; его нельзя раздавать обычным пользователям.

Запросы отправки идемпотентны по `request_id`. Если результат отправки неизвестен из-за обрыва связи, сервис не повторяет её автоматически; перед повтором используйте тот же `request_id`. Повторное использование этого ID с другим содержимым отклоняется.

Результат содержит `status`, `message_id`, `request_id`, `duplicate`. `sent` означает только принятие сообщения Telegram, без гарантии доставки или прочтения. `failed` означает отклонение запроса; `unknown` — неоднозначный результат; `sending` — незавершённую запись, например после аварийной остановки. Для обычной отправки повтор того же ID возвращает сохранённый результат без новой отправки, включая `failed`, `unknown` и `sending`. Создавать новый ID после неоднозначного результата следует только после ручной проверки, иначе возможно повторное сообщение. Текст в базе не сохраняется: хранится SHA-256 отпечаток содержимого и адресатов.

Текст ограничен 4096 единицами UTF-16; при отправке в группу в этот предел входят добавленные имена. Можно указать от 1 до 50 уникальных подтверждённых активных пользователей. Упоминания используют числовые ID и Telegram entities, поэтому HTML в тексте не исполняется. Участие пользователей в группе автоматически не проверяется; видимость упоминаний зависит от правил Telegram. Все сообщения отправляет бот.

## Telegram polling

При запуске сервис проверяет бота через `getMe` и получает его username. Используется long polling; сервис не вызывает `setWebhook`. Если для этого бота ранее был намеренно настроен webhook, удалите его через выбранный вами способ управления Bot API до запуска polling. Сервис сам не меняет эту настройку.

## Входящие сообщения, файлы и ответы

После привязки личное сообщение от активного пользователя попадает во входящие. Обычное сообщение само не вызывает ответ. Сервис сохраняет текст или подпись, Telegram ID отправителя, ID чата, ID сообщения, тему группы и метаданные вложения. Поддерживаются документы, фото, аудио, видео, голосовые сообщения и анимации. Повтор одного Telegram-сообщения не создаёт дубликат. Пересланные, отредактированные сообщения, сообщения ботов, неизвестных и отключённых пользователей не принимаются.

| Инструмент MCP | Действие |
| --- | --- |
| `get_profiles()` | Доступные активные профили: стабильный `id`, имя и nickname. |
| `get_messages(profile_id?, message_id?, after_id?, limit?)` | История или одно входящее. Курсор `after_id`, до 100 элементов за запрос. |
| `get_attachment(attachment_id)` | Содержимое файла по `attachment.id` из входящего. |
| `send_message(profile_id, request_id, text?, message_id?, attachment_id?, file?, send_at?, delay_seconds?)` | Отправить текст или файл выбранному профилю; `message_id` задаёт ответ на входящее. |
| `get_profile()` | Служебная идентификация текущего OAuth-аккаунта для ChatGPT; отмечена как private/app и не предназначена для выбора получателя. |

Например: `get_profiles` → выбор аккаунта → `get_messages` → `get_attachment` →
`send_message` с выбранным `profile_id` и при необходимости `message_id` входящего.

Текст ограничен 4096 единицами UTF-16, подпись к файлу — 1024. За один вызов
отправляется одно вложение: собственное входящее по `attachment_id` либо файл
клиента в `file`. Нельзя сочетать оба источника. `file` использует адаптер
`openai/fileParams`: обязательны `download_url` и `file_id`, необязательны
строковые `file_name` и `mime_type`. ChatGPT передаёт файл через адаптер;
клиенты без этой возможности могут повторно отправлять принятые вложения.
Произвольные URL, локальные пути и чужие Telegram file ID не принимаются.
Файлы клиента скачиваются только с разрешённых HTTPS-доменов провайдера,
без редиректов, с проверкой и закреплением публичного IP и ограничением размера.
Байты немедленной отправки находятся только в памяти; большая загрузка и
отправка используют общую блокировку с получением файлов.

Повтор `request_id` возвращает известный результат без новой отправки.
Смена текста, файла, получателя или reply target под тем же ключом отклоняется.
Неоднозначные сетевые результаты автоматически не повторяются. Старые имена
инструментов принимаются для кэшированных клиентов с прежними проверками доступа,
но не включаются в список инструментов. После обновления клиенту нужно обновить
список действий коннектора.

Отложенные параметры зарезервированы в универсальной отправке. При запрещённом
хранении исходящих запрос с ними отклоняется; клиент не должен объявлять такое
уведомление запланированным без успешного ответа сервера.

Предел MCP — **100 МиБ** (`MAX_ATTACHMENT_BYTES=104857600`). У [облачного Bot API](https://core.telegram.org/bots/api#getfile) собственный предел скачивания **20 МБ**; для больших файлов необходим [локальный Telegram Bot API Server](https://core.telegram.org/bots/api#using-a-local-bot-api-server). Просто смена числа в MCP не снимает ограничение Telegram.

В `get_attachment` файлы до 10 МиБ возвращаются прямо в MCP: UTF-8 текст с предпросмотром, PNG/JPEG/WebP/GIF как изображения, остальные форматы как бинарные resources. Для более крупных файлов или неизвестного размера инструмент возвращает метаданные и `download_path`. В HTTP-режиме клиент скачивает файл через `GET /attachments/{attachment_id}` с тем же `Authorization: Bearer …`. Этот маршрут тоже проверяет Host/Origin и активную привязку; токен в URL не передаётся. Большой файл не кодируется в Base64 внутри контекста модели. Для скачивания через этот маршрут нужен HTTP-транспорт; stdio возвращает только метаданные крупных файлов.

Содержимое загружается по запросу, с проверкой размера и одной одновременной загрузкой. MCP не записывает байты вложений на диск; локальный Telegram Bot API хранит собственный закрытый файловый кэш. В локальном режиме чтение разрешено только внутри `TELEGRAM_LOCAL_FILES_ROOT`, включая проверку открытого файла после разрешения пути. Сервис сам не извлекает текст PDF/Word, не распознаёт голос и не запускает присланные программы. Разбор файла и допустимый объём вложений в AI-чате зависят от клиента.

HTTP-ответ скачивания содержит `X-Accel-Buffering: no`, чтобы nginx не буферизовал
большой ответ во временный файл. Прокси должен учитывать этот заголовок.

`from.id` определяет Telegram-пользователя. `chat.id` определяет Telegram-диалог, а `message_thread_id` — тему группы. В личке пользователь и чат имеют один ID. Username справочный и может меняться. MCP-клиент использует ваш внутренний `user_key`, связанный с числовым ID через приглашение.

Диалог Telegram и чат Codex/ChatGPT — разные сущности. Этот сервер не получает ID вызывающего AI-чата и не выбирает его по Telegram username. Клиент с MCP-токеном имеет операторский доступ ко всем привязкам и входящим; это не разграничение доступа между несколькими независимыми операторами. Чат увидит входящее после вызова инструмента. Автоматическое пробуждение нужного AI-чата, постоянный автоответчик и маршрутизация «этот Telegram-диалог → этот AI-чат» требуют отдельного обработчика событий/маршрутов и в эту версию не включены.

В группах принимаются только сообщения подтверждённых активных отправителей из `ALLOWED_GROUP_CHAT_IDS`, которые Telegram фактически передал боту. Набор таких сообщений ограничивается правами бота и Telegram Privacy Mode; сервис сам не меняет эти настройки и не читает старую историю.

Недоступность бота для пользователя прекращает сохранение новых сообщений, получение новых файлов и отправку этому пользователю. Уже сохранённые входящие остаются доступны оператору; `/unlink` удаляет привязку, но не очищает историю. В отличие от исходящих сообщений, **тексты входящих сохраняются в SQLite** для двусторонней работы. Защищайте базу, резервные копии и MCP-токен как персональные данные.

## Docker Compose

Сначала создайте `.env` по примеру выше и заполните его секреты. Затем соберите образ и запустите контейнер:

```sh
docker compose up --build -d
```

Compose публикует порт только на `127.0.0.1:8000`, хранит SQLite в именованном томе `telegram_ping_data` и запускает процесс без root с файловой системой только для чтения. Не добавляйте реальные токены в `compose.yaml` или образ. Для удалённого доступа используйте HTTPS reverse proxy с аутентификацией MCP и настройте `MCP_ALLOWED_HOSTS`; не публикуйте порт приложения напрямую в интернет.

SQLite рассчитана на один экземпляр сервиса. Для нескольких экземпляров общая база SQLite не поддерживается.

Развёртывание под пользователем `apps` через systemd user описано в [`deploy/README.md`](deploy/README.md). Оно использует отдельный loopback-порт и конфигурацию вне каталога приложения; HTTPS ingress настраивается на сервере отдельно.

При включённом polling процесс удерживает файловую блокировку рядом с базой; второй poller с этой же базой не запустится, а после аварийного завершения блокировка освобождается ОС. Запуск того же бота с другой базой или оставшийся webhook приводит к ошибке Telegram 409: polling прекращается, `/health` отвечает 503, инструменты недоступны до исправления причины и перезапуска. После корректного старта `/health` отвечает 200; `POLLING_ENABLED=false` позволяет работать с существующими связями без получения команд и новых привязок. Команды подключения и `/unlink` в этом режиме не обрабатываются, поэтому используйте его только при осознанном внешнем управлении обновлениями.

Сохраняйте базу и её резервные копии как персональные данные: подтверждённые Telegram ID и имена нужны для работы привязок. В production ограничьте доступ к `.env`, каталогу данных и резервным копиям средствами ОС. Сервис не пишет сообщения и токены в свои логи; не включайте DEBUG/INFO-логи HTTPX, поскольку URL Telegram Bot API содержит токен.


## Уведомления о релизах

Перед production-развёртыванием согласуйте точный финальный русский текст
уведомления. После развёртывания сначала подтвердите установленную версию,
готовность HTTPS и MCP, затем запускайте рассылку. Откаты не рассылаются.

Операторский маршрут `POST /admin/releases/{version}/broadcast` принимает
JSON `{ "message": "одобренный текст", "retry_failed": false }` с операторским
Bearer-токеном. OAuth-подключения пользователей к этому маршруту не допускаются;
версия в пути должна совпадать с установленной. Ответ содержит только числа
`sent` и `failed`. Публичный набор MCP-тулов этот маршрут не расширяет.

Для запуска непосредственно в настроенном runtime доступна команда
`telegram-ping-mcp broadcast-release --message-file PATH`. Она не запускает
polling. Ключ `--retry-failed` повторяет только подтверждённые неудачи.

Рассылка тихая и однократная для версии и привязки. Исходящий текст не
сохраняется: SQLite содержит отпечатки, статусы и ID принятых сообщений.
Первый запуск фиксирует отпечаток одобренного текста для всей версии;
изменённый текст этой же версии отвергается до отправки новым получателям.
Неоднозначные результаты и незавершённые попытки не повторяются.
Перед отправкой проверяются актуальные права; прежние slash-меню очищаются,
а HTTP-рассылка сохраняет текущий режим reply-клавиатуры пользователя.

```sh
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run pytest
uv build
```

Автоматические тесты не отправляют реальные сообщения. Ручную проверку доставки выполняйте только для заранее названного получателя, который явно согласился получить тестовое сообщение.

Протокол реализован через [официальный Python SDK MCP](https://github.com/modelcontextprotocol/python-sdk). Взаимодействие с Telegram следует [Bot API](https://core.telegram.org/bots/api); личный аккаунт и ключ OpenAI API не нужны.
